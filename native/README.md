# Gem City SQL Investigation

The final student-facing native app is published under `/js/`. The original Streamlit implementation and existing published root remain intact. Source branch: `rollout/native-browser`; static branch: `stlite-browser`. Native publication changes only `/js/`, without changing Pages settings or adding any storage service.

All original six stages, SQL samples, answer-specific hints, normalized schema, corrected-query outputs and both reporting assignments are retained. SQL runs in a dedicated worker using locally packaged, integrity-verified SQLite 3.50.4. The SQLite C authorizer allows SELECT/READ/FUNCTION/RECURSIVE operations and denies writes, PRAGMA, attachments, transactions and extension/file functions. A query-only database adds enforcement. SQLite parses the entire query, so literals/comments containing SQL words or semicolons remain valid while multiple actual statements are rejected. Fresh in-memory databases preserve the original data. Limits: 8,000 input characters, 100 result rows, 1 MiB value/result bounds, a 1.5-second VM execution deadline and 4-second worker deadline including startup. Cancellation terminates the worker and retains draft/progress; a subsequent query starts normally. Real worker tests cover ten Python result oracles, CTEs, joins, functions, window functions, NULLs, duplicate columns, mutation rejection, row/time limits and recovery. Native grading matches Python binary-float rounding fixtures. CSV exports retain raw query values while tables retain currency/percentage formatting. No Python runtime is loaded. UTF-8 output byte accounting and recovery have additional focused worker coverage; first-worker timing and measurement conditions are in review/sql-worker-bounds.json.

Valid original version-3 progress links import at /js/ with exact 63-bit shuffle seeds and Python option ordering. Saved submitted SQL is reexecuted in the real worker before a passed flag can unlock progress. Native links use version 4 to preserve unfinished revisions and counters beyond the original 99-attempt cap; open them at /js/, because the original Python/root app does not accept version 4. Refresh/bookmarks retain both editor drafts, submitted outputs, attempts and viewed position. Back/Forward are readonly and stop at earned progress. No central storage or new service is added.

Build with `python native/build.py`. Export original content with the repository's prepared interpreter using `python native/export.py`; Python is build/testing tooling only and is never loaded in the delivered app. Validate with the original repository suite, `node --test native/tests/*.test.mjs`, ESLint, and `python native/tests/browser.py` after building. See [VALIDATION.md](VALIDATION.md), [browser results](review/browser-results.json) and screenshots in `review/`.
